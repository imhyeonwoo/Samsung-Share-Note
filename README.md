GitHub Pages + Firebase로 만든 노션형 공동 편집 워크스페이스입니다.

배포 예정 주소: https://imhyeonwoo.github.io/Share-Note/

## 끊어진 하위 페이지 링크 정리 (2026-11-11)

기존 블록에서 생성된 하위 페이지를 삭제하더라도, 나중에 변환된 Tiptap 문서에 남은 **페이지 참조 카드**는 자동으로 삭제되지 않을 수 있습니다. 페이지 목록에 대상 ID가 없으면 이 카드는 정상 페이지가 아니라 끊어진 링크로 표시됩니다.

- 정상적인 하위 페이지 링크는 그대로 클릭해서 이동합니다.
- 대상 페이지가 없는 카드는 **연결이 끊어진 페이지 · 대상 페이지를 찾을 수 없음**으로 표시됩니다.
- 카드의 **링크 제거** 버튼을 클릭하고 확인하면 해당 **본문 내 링크 카드 하나만** 제거합니다. 다른 페이지나 정상 카드 내용은 삭제하지 않습니다.
- 페이지 목록이 실시간으로 변경되면 카드의 제목과 상태를 새로 표시합니다.
- 끊어진 카드에서 페이지 원본을 자동 복원하지는 않습니다. 원본 복구는 Firebase 백업 또는 삭제 전 원본 자료가 필요한 별도의 작업입니다.
- 기존 문서의 끊어진 링크를 자동 삭제하지 않아 팀원 자료가 예기치 않게 사라지는 것을 방지합니다.

## 표 크기 조절 (2026-11-11)

- **열 너비 조절:** 표의 두 열 사이 경계선 위로 마우스를 올린 뒤 나타나는 리사이즈 경계선을 좌우로 드래그합니다.
- **표 전체 너비 조절:** 표 오른쪽 아래의 `↔` 손잡이를 드래그합니다. 각 열 너비가 비율에 맞게 함께 늘거나 줄어듭니다.
- **행 높이:** 셀 내용에 따라 자동으로 조정됩니다.
- **저장/공유:** 열 너비가 Tiptap의 셀 `colwidth` 속성으로 문서 JSON에 저장됩니다. 기존 Firebase 자동 저장/공유 동기화를 그대로 사용합니다.
- **큰 표:** 본문보다 넓어진 표는 가로 스크롤로 확인할 수 있습니다.

이 기능은 기존 표에도 적용됩니다. Firebase 보안 규칙 변경은 필요하지 않습니다. Chromium 자동 테스트에서 열 경계 드래그, 표 전체 너비 드래그, 열 너비 값의 저장을 확인했습니다.

## LaTeX 수식 · 조절 가능한 사이드바 (2026-11-11)

### 수식 입력 및 수정

- 문서 본문에서 `/math` 또는 `/수식`을 입력한 다음 **수식 블록**을 선택하거나 상단 **∑ 수식** 버튼을 클릭합니다.
- 문장 중간에 수식이 필요하면 `/math-inline` 또는 **𝑥 인라인**을 사용합니다.
- 수식 입력창에서 LaTeX를 입력하면 KaTeX 미리보기가 즉시 갱신됩니다. **Ctrl+Enter**(Mac: Cmd+Enter)로 입력할 수도 있습니다.
- 수식 자체를 클릭하거나 키보드로 선택하여 Enter를 누르면 수식 내용을 다시 편집할 수 있습니다.
- `Z=\\sqrt{R^2+(X_L-X_C)^2}`, `P=VI\\cos\\theta` 등의 수식을 지원합니다.
- 수식의 **LaTeX 원본**은 다른 본문과 함께 자동 저장·공유됩니다. HTML 실행 권한을 허용하지 않는 KaTeX 안전 설정을 사용합니다.

### 사이드바 크기 조절 및 접기

- **PC:** 왼쪽 사이드바의 오른쪽 경계선을 가로로 드래그하면 너비가 약 **210–480 px** 범위에서 변경됩니다. 경계선을 포커스한 뒤 **← / →** 키로도 조절할 수 있습니다.
- 상단 좌측 **☰ 버튼**을 누르면 사이드바가 옆으로 접히면서 본문이 넓어집니다. 다시 누르면 펼쳐집니다.
- 사이드바 상단 **‹ 버튼**으로도 접을 수 있습니다.
- **모바일:** 상단 ☰ 버튼으로 메뉴를 열고 사이드바 상단 ‹ 버튼으로 닫습니다.
- 사이드바 폭과 접힘 여부는 **각 사용자의 브라우저**에 저장됩니다. 공유 워크스페이스의 문서 구조나 다른 팀원의 화면 설정에는 영향을 주지 않습니다.

이 변경으로 Firebase 보안 규칙을 다시 게시할 필요는 없으며 기존 문서와 하위 페이지는 그대로 유지됩니다.

## 편집기 2.0: 통합 문서 편집

기존 Folio의 분리된 textarea 입력창 대신 **Tiptap 3 기반 통합 리치 텍스트 편집기**가 기본으로 표시됩니다.

- 문서 전체 드래그 선택, Ctrl+A / Ctrl+C / Ctrl+V, 여러 문단 사이 자유로운 커서 선택
- 붙여넣기 시 HTML의 굵게/기울임/표 서식을 인식. 순수 Markdown 텍스트의 **굵게**, 제목, GitHub 스타일 파이프 표도 변환
- 제목 1~3, 굵게/기울임/취소선, 글머리/번호 목록, 체크리스트, 인용문, 코드 블록, 표(행·열 수정)
- 문서 본문에서 `/`로 삽입 메뉴 검색. 하위 페이지·이미지 삽입 및 업로드 유지
- Ctrl+Z 실행 취소와 문서 전체 복사, JSON 백업 다운로드
- Firebase 실시간 **최신 문서 반영**, 자동 저장. 단, 동시 사용자 *동일 문서 편집*은 글자 단위 공동 편집(CRDT)이 아니라 **충돌 감지 후 저장 중지** 방식입니다. 충돌 시 내 초안 복사/백업 후 최신 내용을 다시 불러옵니다.

**기존 데이터 보존:** 처음 열 때 기존 `blocks` 문서들을 읽어 임시로 변환합니다. 사용자가 실제로 편집한 이후에만 같은 `blocks` 컬렉션 내 별도의 예약 ID에 새 문서(JSON)를 저장합니다. 기존 문단 레코드 및 이미지 레코드는 삭제하지 않아 데이터가 남습니다. 원본을 수동 복구하려면 GitHub 저장소의 이전 버전 코드를 이용하거나 저장된 legacy blocks를 확인할 수 있습니다. 한 페이지당 새 문서 저장 분량은 약 48만 자 JSON으로 제한됩니다.

**Firebase 재설정 불필요:** 새 문서는 이미 허용된 `blocks` 레코드 여러 개에 나눠 저장하므로 Firestore 규칙을 다시 게시할 필요가 없습니다. 이미지는 기존 `images` 권한이 활성화되어 있어야 합니다.

**비상 복구:** 브라우저에 미저장 초안이 감지되면 복원 안내를 띄웁니다. 공동 편집 충돌로 저장이 중단되면 반드시 백업을 먼저 내려받으세요. 한 페이지 안에서 실제 Google Docs처럼 충돌 없이 동시 타이핑하는 기능은 제공하지 않습니다.

**실행 환경:** GitHub Pages + Firebase는 그대로 유지합니다. Tiptap과 ProseMirror 의존성은 GitHub Actions에서 하나의 `rich-editor.bundle.js`로 묶어 배포합니다. CDN에서 개별 모듈을 중복 로드하는 방식은 더 이상 사용하지 않습니다. 기존 데이터는 유지되며 새 번들은 Chromium 자동 테스트를 통과한 상태에서만 사이트에 연결합니다.

## 기능

- 페이지 트리와 하위 페이지 생성, 검색, 이동 및 삭제
- 페이지 제목·이모지 아이콘 변경
- 텍스트, 제목 1~3, 글머리 목록, 번호 목록, 체크리스트, 인용, 코드, 구분선, 이미지 블록
- 블록 추가, 종류 변경, 이동, 복제, 삭제
- Firebase 연결 시 자동 저장 및 실시간 동기화
- 공유 링크를 가진 누구나 회원가입이나 로그인 화면 없이 공동 편집
- 모바일에서도 사용 가능

현재는 초기 버전으로, PDF·일반 파일 업로드, Notion식 관계형 데이터베이스, 댓글, 권한별 초대, 완전한 변경 이력, 삭제 복원은 제공되지 않습니다. 같은 블록을 동시에 편집하면 마지막 저장 내용이 우선할 수 있습니다.

## 글쓰기 편의 기능 (편집기 개편)

- 페이지가 비어 있으면 본문의 **클릭해서 글쓰기 시작**을 누르면 첫 문단으로 바로 진입합니다.
- 문단에서 **Enter**를 누르면 다음 문단이 자동으로 만들어지고, **Shift+Enter**는 같은 문단 안에서 줄바꿈합니다.
- 텍스트 입력 중 **Backspace**를 문단 맨 앞에서 누르면 앞 문단과 합치며, 빈 목록에서 Backspace를 누르면 기본 텍스트로 돌아갑니다.
- 문단 맨 앞에서 **# / ## / ### / - / 1. / >** 뒤에 공백을 입력하면 제목·목록·인용으로 자동 바뀝니다.
- 본문에서 **/**를 입력하면 텍스트, 제목 1·2·3, 글머리 목록, 번호 목록, 체크리스트, 인용, 코드, 구분선, 하위 페이지, 이미지 업로드, 이미지 URL 등 **13개 명령**을 검색할 수 있습니다. 위/아래 방향키와 Enter로 선택할 수 있습니다.
- **여러 줄 텍스트 붙여넣기**는 기존 문단의 커서 위치를 기준으로 나누어 삽입합니다. 마크다운 제목/목록/체크리스트를 인식합니다. 한 번에 너무 많은 내용을 넣으면 일부는 묶인 문단으로 저장될 수 있습니다.
- **전체 내용 복사** 버튼은 현재 페이지를 마크다운 형태의 일반 텍스트로 복사합니다.
- 상단에서 자동 저장 중 / 완료 / 오류 여부를 확인할 수 있습니다.

**현재 제한:** 이 편집기는 텍스트 기반이며, Word/웹사이트에서 가져온 굵게·밑줄·글자색 같은 *인라인 서식은 붙여넣기 시 유지되지 않습니다*. 블록 간 자유로운 마우스 영역 선택, 협업 동시 커서, 전체 문서 실행 취소, 버전 기록은 아직 지원하지 않습니다. 기존 데이터는 그대로 남으며 Firebase 보안 규칙을 새로 게시할 필요는 없습니다.

## 페이지 이동 및 브라우저 뒤로 가기

페이지를 이동할 때 브라우저 방문 기록이 생성되어 **뒤로 가기**로 이전 페이지(예: 하위 페이지에서 부모 페이지)로 돌아갈 수 있습니다. **앞으로 가기**도 지원합니다. 페이지별 주소는 기존 워크스페이스 공유 식별자 뒤에 `&page=페이지ID`가 추가되는 방식입니다. 공유 버튼은 여전히 전체 워크스페이스 링크를 복사합니다. 주소에 페이지 ID가 포함된 링크를 직접 열면 해당 페이지로 이동합니다.

## 본문 안에 하위 페이지 만들기 (/page)

1. 원하는 **부모 페이지**를 엽니다.
2. 빈 텍스트 블록에서 `/page`를 입력하고 **Enter**를 누르세요. `\\page` 입력도 지원합니다.
3. 자동으로 만들어진 **하위 페이지**로 이동하므로 제목과 내용을 작성합니다.
4. 상단의 페이지 경로에서 부모 페이지를 클릭하면 본문에 **📄 하위 페이지 링크 블록**이 생겨 있는 것을 볼 수 있습니다.
5. 그 블록을 누르면 하위 페이지로 이동합니다. 하위 페이지는 왼쪽 사이드바에도 표시됩니다.

- 본문의 **하위 페이지 추가** 버튼을 눌러도 됩니다.
- 기존 블록의 **종류 선택 → 하위 페이지**로 만들어도 됩니다.
- 링크 블록을 삭제해도 하위 페이지 자체는 사이드바에 남습니다. 하위 페이지 자체를 삭제할 때는 해당 페이지에서 **페이지 삭제**를 선택하세요.
- 이 기능은 기존 Firestore 규칙에서 허용된 텍스트 블록에 페이지 참조를 기록하므로 **새로운 보안 규칙 게시가 필요하지 않습니다.**

## 이미지 삽입 (/image)

다음 세 가지 방법을 지원합니다.

1. 빈 텍스트 블록에서 `/image` 입력 후 **Enter** → PC에서 PNG/JPEG/WebP 파일 선택
2. 이미지 파일을 클립보드에 복사한 후 텍스트 블록 안에서 **Ctrl+V** (Mac은 Cmd+V)
3. 본문의 **이미지 업로드**, **이미지 URL 삽입** 버튼 사용 (HTTPS 이미지 주소)
4. 문서 본문으로 이미지 파일을 드래그 앤 드롭할 수도 있습니다.

사진은 브라우저에서 자동으로 WebP/JPEG로 압축·축소한 뒤 **Firestore의 images 컬렉션**에 저장됩니다. Cloud Storage 결제 플랜이 필요하지 않습니다. 원본 15MB 이하, 저장 데이터 약 0.5MB 이하로 제한되며 고화질 원본 보관용이 아닙니다. 지원 형식은 PNG, JPEG, WebP이며 GIF 애니메이션은 지원하지 않습니다.

**반드시 해야 할 추가 설정:** 기존에 Firebase Firestore 보안 규칙을 게시한 사용자는 GitHub 저장소의 **최신** [firestore.rules](./firestore.rules)를 다시 복사하여 Firebase Console → Firestore Database → 규칙(Rules) → 게시(Publish)를 진행해야 실제 이미지 업로드가 가능합니다. 이 규칙에서 기존 페이지·본문에 더해 작은 압축 이미지 기록의 저장/읽기/삭제를 허용합니다.

외부 이미지 URL은 원본 사이트의 정책에 따라 표시가 차단되거나 주소가 만료될 수 있습니다.

## 1. GitHub Pages 배포

1. 저장소 Settings → General에서 필요 시 Public으로 변경 (GitHub Free에서는 Pages를 위해 일반적으로 공개 저장소 필요)
2. Settings → Pages → Build and deployment
3. Deploy from a branch → main / (root) 선택 후 Save
4. 배포 완료 후 위의 주소 방문

Public 저장소의 코드와 Firebase 웹 설정값은 누구에게나 공개됩니다. 실제 문서 내용을 GitHub 저장소에 올리지 마세요.

## 2. Firebase 연결 — 실시간 공유에 필수

1. https://console.firebase.google.com/ 에서 프로젝트를 만듭니다.
2. 프로젝트 설정에서 웹 앱을 추가하고 Firebase 웹 설정 객체를 확인합니다.
3. 저장소의 firebase-config.js 파일에서 REPLACE_ME 등의 값을 Firebase 웹 설정값으로 교체합니다. Firebase Admin SDK 개인 키, 서비스 계정 JSON, 관리자 토큰, 비밀번호는 절대 업로드하지 마세요.
4. Authentication → Sign-in method에서 Anonymous(익명) 로그인 제공업체를 활성화합니다. 사용자는 로그인 화면을 보지 않지만 브라우저가 Firebase 익명 인증을 수행합니다.
5. Firestore Database를 생성하고 Rules 탭에서 저장소의 firestore.rules 내용을 그대로 붙여넣어 Publish합니다. 테스트용 전체 허용 규칙을 그대로 운영하지 마세요.
6. GitHub Pages를 새로고침합니다. 브라우저에서 고유 워크스페이스 주소가 생성되고 공유 버튼을 눌러 주소를 복사할 수 있습니다.
7. 다른 사람은 그 *전체 주소*로 접속하면 같은 페이지와 본문을 바로 편집할 수 있습니다.

firebase-config.js가 미설정 상태면 로컬 브라우저의 체험 모드입니다. 이 경우 다른 사람에게 공유되지 않으며 브라우저 데이터 삭제 시 사라집니다. 기존 체험 모드 데이터는 Firebase로 자동 이관되지 않습니다.

## 공유 링크에 관한 주의사항

공유할 때는 사이트 주소만이 아니라 끝에 #space= 및 48자리 식별자가 붙은 전체 URL을 전달해야 합니다. 각 워크스페이스의 식별자는 브라우저가 생성한 192비트 난수입니다.

- 링크를 가진 누구나 읽기, 추가, 수정, 삭제가 가능합니다.
- 이 방식은 비밀 URL을 이용하는 편의형 공유이지 사용자별 인증이나 엄격한 접근 통제가 아닙니다.
- 링크가 재전송되거나 노출되면 제3자도 편집할 수 있습니다.
- 삭제 복구 및 편집 이력 기능은 없습니다. 중요하거나 민감한 자료를 넣지 마세요.
- Firebase 익명 인증을 사용하며, 공개 편집은 도배/악용이나 사용량 급증 위험이 있습니다. Firebase 사용량 및 예산 알림을 설정하고 규모가 커질 경우 App Check, 백업, 서버 측 권한 제한 등을 추가하세요.

## 로컬 실행

별도의 빌드 도구가 필요하지 않습니다. 프로젝트 폴더에서 python -m http.server 8000을 실행하고 http://localhost:8000 으로 접속합니다.
